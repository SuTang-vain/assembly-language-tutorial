## 17. 传送方向：单工 / 半双工 / 全双工（8251A 是全双工）

**层级** 理解 ｜ **来源** `章+网` ｜ **正文** §2.1

### ① 机理详解

三种方向按「能不能同时双向传」排列：

| 方向 | A→B | B→A | 同时？ | 典型例子 |
|---|---|---|---|---|
| **单工** Simplex | ✔ | ✘ | — | 广播、键盘只送 |
| **半双工** Half-Duplex | ✔ | ✔ | ✘（轮流） | 对讲机 |
| **全双工** Full-Duplex | ✔ | ✔ | **✔** | 电话、**8251A** |

**8251A 是全双工**：芯片内部发送通道与接收通道**相互独立**，各有自己的
缓冲器、移位寄存器和时钟（TxC 与 RxC 分开），所以可以一边发一边收，
共用一根传输线（收发用不同线）或两根线。

### ② 例题

某系统用一对导线，两端都要能说、但同一时刻只能一方说。问属于哪种方向，
能否用 8251A 实现？

```
属于半双工（轮流说）。
8251A 本身支持全双工，硬件能力足够；实现半双工只需在软件上控制：
同一时刻只允许一端的 TxEN=1、另一端 TxEN=0，通过握手（如 RTS/CTS）切换。
所以「能全双工的芯片」可以降级用成半双工，反之不行。
```

### ③ 易错提示

- **全双工 ≠ 两根线**：全双工的关键是「**同时**双向」，不是线路数量。
- 8251A 的 TxD 与 RxD 是**两个独立引脚**，这就是全双工的硬件基础；
  别和 RS-232 的「一根发一根收」混淆。
- 老师对本条只要求「理解」——能列表区分三种方向即可。

### ④ 横向辨析

| | 单工 | 半双工 | 全双工 |
|---|---|---|---|
| 信道数 | 1 | 1 | 2（或 1 根频分复用） |
| 8251A 支持 | ✔ | ✔（软件降级） | ✔（原生） |
| 效率 | 低 | 中 | 高 |

## 18. 同步 vs 异步：成帧方式、时钟要求、效率

**层级** 了解 ｜ **来源** `师+章` ｜ **正文** §2.1

### ① 机理详解

两者的根本区别是「**收发双方如何对齐字节边界**」：

| | 异步（起止式） | 同步 |
|---|---|---|
| 成帧单位 | **单个字符** | **数据块** |
| 同步方式 | 每字符前加起始位重新同步 | 用**同步字符**（1~2 个）锁定一次，后续连续传 |
| 时钟要求 | 不严格（收发频率接近即可，靠起止位容错） | **严格同相** |
| 开销 | 每字符 2 位以上起止位，**开销大** | 仅块首几个同步字符，**开销小** |
| 效率 | 低 | **高** |
| 适用 | 低速、断续发送 | 高速、连续大数据块 |
| 8251A 均支持 | ✔ | ✔ |

为什么异步能容忍时钟误差：起始位的下降沿让接收端「重新对表」，
只要一字节内累积的相位偏差不超过半个位时间就能正确采样。
所以异步不需要收发时钟严格同相，但**波特率必须约定一致**。

### ② 例题

异步方式每字符 1 起始 + 8 数据 + 1 停止 = 10 位；同步方式每块 2 同步字符 + 100 数据字节。
比较两者的有效信息效率。

```
异步：每字符 10 位传 8 位数据 → 效率 = 8/10 = 80%
同步：2 同步字符 + 100×8 = 800 位数据，总位 = 16 + 800 = 816
      效率 = 800/816 = 98.0%

→ 数据块越长，同步的效率优势越明显。这正是高速通信选同步的原因。
```

### ③ 易错提示

- **「同步」指的是帧同步，不是时钟同步**（虽然同步方式对时钟要求也更严）。
  答「同步就是时钟相同」不完整——关键是「**用同步字符对齐数据块**」。
- 别答反：异步开销大、效率低；同步开销小、效率高。
- 8251A **两种方式都支持**，靠方式字选择（条目 24）。这是它相对 8250 的特点之一。

### ④ 横向辨析

| | 异步 | 同步 |
|---|---|---|
| 起始/同步标志 | 起始位（每字符） | 同步字符（每块） |
| 结束标志 | 停止位 | 无（靠约定长度/CRC） |
| 8251A 检测引脚 | — | **SYNDET**（同步检测） |
| 初始化 | 4 步（条目 29） | **5 步**（条目 30，多写同步字符） |
| 命令字 | 15H | **95H**（多 EH 启动搜索同步） |

## 19. 异步帧格式：起始位 0 / 数据 5~8 位低位先发 / 校验 / 停止位 1~2

**层级** 掌握·必背 ｜ **来源** `章+网` ｜ **作业题** 第9讲Q2 ｜ **正文** §2.1

### ① 机理详解

异步一字符的线上时序（**低位先发**是关键）：

```
空闲:  11111111...

起始位: 0            ← 1 位，一定是 0（下降沿 = 「我要开始了」）
数据位: D0 D1 D2 D3 D4 D5 D6 D7   ← 5~8 位，**最低位 D0 最先上线路**
校验位: P            ← 0 或 1 位，可无
停止位: 1            ← 1、1.5 或 2 位，一定是 1（回到空闲）

空闲:  11111111...
```

要点：

- **空闲位是高电平 1**，所以起始位的下降沿就是同步信号。
- **数据位低位先发**（LSB first）：发送端把数据的最低位先放上 TXD。
  这与 8086 并行总线的「小端」是不同层面的概念，但都是「低位在前/低位在低地址」。
- **校验位可选**：奇校验让 1 的个数为奇，偶校验为偶；8251A 由方式字 D5D4 选。
- **停止位一定是 1**，用于保证字符之间有间隔，给接收端留同步余量。

### ② 例题

**真题（课堂练习 8251 Q3，单选）**：关于 8251A 的异步通信数据格式，下列说法**错误**的是？

```
选项：
  A 无传输时发送空闲位（空闲位是高电平）
  B 数据传输前先发送 1 位起始位（起始位是低电平）
  C 数据位只能是 8 位          ← 错的就是这项
  D 最后还要发送停止位（可以是 1 个、1.5 个、2 个）

答案：C
```

逐项核对：

| 选项 | 判定 | 依据 |
|---|---|---|
| A | ✔ | 空闲位是高电平 1（本条①的时序图） |
| B | ✔ | 起始位固定 1 位且为 0 |
| **C** | **✘** | **数据位 5~8 位，由方式字 D3D2 选**（条目 24） |
| D | ✔ | 停止位 1 / 1.5 / 2 位，由方式字 D7D6 选 |

> **本题的陷阱**：「错误的一项是」+ 「数据位只能是 8 位」听起来最像常识。
> 8251A 支持 5~8 位，8N1 只是最常用配置，不是唯一。



第9讲 Q2 要求同步方式（见条目 30）；这里用一道同型异步题：按「1 起始 + 8 数据 + 偶校验 + 1 停止」
发送 0C3H，画出线上波形的高低电平序列。

```
0C3H = 1100 0011B
数据位低位先发：D0=1, D1=1, D2=0, D3=0, D4=0, D5=0, D6=1, D7=1
偶校验：1 的个数 = 6（偶数）→ 校验位 P = 0

线上序列：
  空闲  1 1 1 ...
  起始  0
  数据  1(D0) 1(D1) 0(D2) 0(D3) 0(D4) 0(D5) 1(D6) 1(D7)
  校验  0
  停止  1
  空闲  1 1 1 ...
```

共 11 位：1 + 8 + 1 + 1。

### ③ 易错提示

- **低位先发**：0C3H 的数据位序列是 11000011（按 D0→D7 读），不是 11000011 倒过来。
  画波形时最容易把 D7 画在最前。
- **起始位是 0、停止位是 1**，别写反（写反就没有下降沿可同步了）。
- 帧格式是**必背**：空闲(1) → 起始(0) → 数据(5~8，低位先发) → 校验(0/1) → 停止(1/1.5/2)。
- 本讲易错第 3 条（主文档 §2.5）：**「帧计算漏起止位」**——算波特率时 8 数据位要按 10 位算
  （见条目 20）。

### ④ 横向辨析

| | 异步帧 | 8086 小端存储 |
|---|---|---|
| 「低位在前」的含义 | 线上**先出现** D0 | 内存**低地址**放低字节 |
| 作用对象 | 时间轴 | 地址轴 |
| 共同点 | 都是「低位优先」 | |

## 20. 波特率 vs 比特率计算（只数数据位）

**层级** 掌握·必考计算 ｜ **来源** `师+章` ｜ **作业题** 第9讲Q2 ｜ **正文** §2.1

### ① 机理详解

两个概念的分界线是「**只数数据位**」：

$$\text{波特率} = \frac{\text{线上总位数}}{\text{秒}} \qquad
\text{比特率} = \frac{\text{数据位数}}{\text{秒}}$$

- **波特率（Baud）**：线上信号变化的速度，**所有位都算**（起始 + 数据 + 校验 + 停止）。
  二进制调制下 1 波特 = 1 bit/s。
- **比特率（bit/s）**：**只数有效数据位**。

以主文档的例子（1 起始 + 7 数据 + 1 校验 + 1 停止 = 10 位/字符，每秒 120 字符）：

```
波特率 = 10 位/字符 × 120 字符/秒 = 1200 波特
比特率 =  7 位/字符 × 120 字符/秒 =  840 bit/s
```

差值 360 bit/s 就是起止位和校验位「吃掉」的开销。

**与 8253 的联动**：8251A 自己没有波特率发生器，TxC/RxC 时钟通常由 8253 提供：

```
f_CLK = 波特率 × 波特率因子        （因子 ×1 / ×16 / ×64，由方式字 D1D0 定）
```

### ② 例题

**真题（课堂练习 8251 Q2，单选）**：异步通信，数据格式 1 起始 + 8 数据 + 0 校验 + 1 停止，
每秒传 200 个字符，波特率因子设为 16，求发送时钟 TXC 的频率。

```
① 每字符线上位数 = 1 + 8 + 0 + 1 = 10 位
② 波特率 = 10 位/字符 × 200 字符/秒 = 2000 波特
③ TXC = 波特率 × 因子 = 2000 × 16 = 32 000 Hz = 32 kHz

答案：C（32KHz）

干扰项：
  A 100Hz    ← 只算了 200×0.5，数量级错
  B 25.6KHz  ← 把 10 位算成 8 位（漏起止位）：8×200×16 = 25.6K
  D 64KHz    ← 因子用错成 32：2000×32 = 64K（32 不是合法因子，见条目 24）
```

> **B 项正是本讲易错第 3 条**「帧计算漏起止位」。漏了起始位与停止位，
> 结果从 32K 掉到 25.6K——差了 25%。
> **D 项则是条目 24 的伏笔**：32 倍不是 8251A 的合法波特率因子。



作业第9讲 Q3 的波特率设计：8086 + 8251（基址 300H）+ 8253（基址 304H），
时钟 2MHz，波特率 4800 Bd，波特率系数 16。求 8253 的计数初值。

```
① 8251 需要的收发时钟：
   f_CLK = 4800 × 16 = 76 800 Hz = 76.8 kHz

② 8253 的初值（8253 时钟 2 MHz = 2000 kHz）：
   N = 2 000 000 ÷ 76 800 = 26.04

③ 取整：N = 26（作业标准答案）

④ 实际效果（取整带来的误差）：
   实际 f_CLK = 2 000 000 / 26 = 76 923 Hz
   实际波特率 = 76 923 / 16 = 4807.7 Bd
   误差 = (4807.7 − 4800) / 4800 ≈ +0.16%  ← 可接受

作业控制字：MOV AL, 00010111B   ; CNT0、只写低字节、方式3(方波)、BCD
            MOV DX, 30AH        ; 8253 控制口
            MOV DX, 304H        ; 8253 计数通道 0
            MOV AL, 26H         ; 初值（BCD）
```

> 注意这里是 **BCD 计数**（控制字 D0=1），所以初值写 26H（BCD 的 26）而不是 1AH（二进制的 26）。

### ③ 易错提示

- 本讲易错第 2 条（主文档 §2.5）：**「波特率因子 ≠ 波特率」**。
  ×16 是「每个比特用 16 个时钟采样/移位」，不是波特率乘 16 的意思——
  但**时钟频率 = 波特率 × 因子**，方向别搞反。
- 本讲易错第 3 条：**「帧计算漏起止位」**。8 数据无校验 1 停止，线上是 10 位。
- **BCD 与二进制初值要分清**：N=26 在 BCD 方式写 26H，在二进制方式写 1AH。
  这是 Q3 的高频错点（控制字 D0=1 决定）。

### ④ 横向辨析

| | 波特率 | 比特率 |
|---|---|---|
| 数的对象 | 线上全部位 | **仅数据位** |
| 单位 | 波特（Bd） | bit/s |
| 二进制调制下 | 数值上相等（当只有数据位时） | — |
| 与 8253 的关系 | 波特率 × 因子 = TxC/RxC 频率 | 无关 |

**考试口诀**：算波特率数**起止位**，算比特率只数**数据位**。

## 21. 8N1 = 10 位/字符；字节速率 = 波特率÷10

**层级** 掌握 ｜ **来源** `章+网` ｜ **作业题** 第9讲Q2 ｜ **正文** §2.1

### ① 机理详解

**8N1** 是最常用的帧配置，含义：

```
8    = 8 个数据位
N    = No parity，无校验位
1    = 1 个停止位
加上 1 个起始位 → 每字符线上共 10 位
```

推论：

$$\text{字节速率（B/s）} = \frac{\text{波特率}}{10}$$

例如 9600 波特 → 960 B/s。这是串口调试助手里「波特率 9600」对应的实际文件传输速度上限。

其他常用配置：

| 配置 | 每字符位数 | 波特率 9600 时的字节速率 |
|---|---|---|
| 8N1 | 10 | 960 B/s |
| 8E1（偶校验） | **11** | 873 B/s |
| 8O1（奇校验） | **11** | 873 B/s |
| 7E1 | 10 | 960 B/s |
| 8N2 | 11 | 873 B/s |

### ② 例题

波特率 19200，帧格式 8E1，求每秒最多传多少字节，并写出对应的 8251A 方式字。

```
每字符位数 = 1 + 8 + 1 + 1 = 11
字节速率 = 19200 / 11 ≈ 1745 B/s

方式字（8 数据 + 偶校验 + 1 停止，设 ×16）：
  D7D6 = 01   （1 停止位）
  D5D4 = 11   （偶校验）
  D3D2 = 11   （8 数据位）
  D1D0 = 10   （×16）
  → 0111 1010B = 7AH    ← 正是作业第9讲 Q3 第2空的正确答案
```

### ③ 易错提示

- **8E1 是 11 位不是 10 位**：校验位也要占线上时间。
- 别把「字节速率」和「波特率」直接划等号——只有 8N1 时恰好是 1/10，
  换成 7 数据位无校验（8 位/字符）时是 1/8。
- **7AH 与 4EH 的差别就在校验位**（4EH 是 8N1，7AH 是 8E1），两个都是真题答案，
  别记混。

### ④ 横向辨析

| 方式字 | 二进制 | 配置 |
|---|---|---|
| **4EH** | 0100 1110 | 8 数据 / **无校验** / 1 停止 / ×16 |
| **7AH** | 0111 1010 | 8 数据 / **偶校验** / 1 停止 / ×16（Q3 答案） |
| 5BH | 0101 1011 | 7 数据 / 奇校验 / 1 停止 / ×64（Q3 干扰项） |
| 38H | 0011 1000 | **同步**：双同步字符 / 内同步 / 偶校验 / 7 数据（Q2/Q4 答案） |

## 22. Modem 远距离通信

**层级** 了解 ｜ **来源** `师+章` ｜ **正文** §2.4

### ① 机理详解

TTL 电平的串行信号传输距离很短（几米内），远距离要经 **MODEM（调制解调器）**
把数字信号调制成模拟信号走电话线/专线，对端再解调。

因此 8251A 提供了一组 **Modem 联络信号**：

| 引脚 | 方向 | 含义 |
|---|---|---|
| **DTR**（Data Terminal Ready） | 输出 | 数据终端准备好 |
| **DSR**（Data Set Ready） | 输入 | 数据装置（Modem）准备好 |
| **RTS**（Request To Send） | 输出 | 请求发送 |
| **CTS**（Clear To Send） | 输入 | 允许发送（Modem 的应答） |
| **DCD** | 输入 | 数据载波检测 |

典型的握手链：DTE 拉高 DTR → Modem 回 DSR → DTE 拉 RTS → Modem 回 CTS → 开始发数据。

**近距双机通信可以不用 Modem**：三线（TXD/RXD/GND）直连即可，但此时
**CTS 要接地**（常有效），否则 TxRDY 引脚不会就绪（见条目 28）。

### ② 例题

两台 8086 系统用 8251A 近距通信，只用 TXD/RxD/GND 三线对接，发现发送端 TxRDY 引脚
永远不就绪。分析原因。

```
原因：TxRDY 引脚有效 = 发送缓冲器空 ∧ CTS̄ 有效 ∧ TxEN=1
三线直连时 CTS 悬空/未接，不满足「CTS̄ 有效」，所以引脚不就绪。

解决：把对端（或本端，直连时自己）的 CTS̄ 接地置有效；
      或者改用「读状态字的 D0」来判断发送就绪，绕开引脚条件。
```

### ③ 易错提示

- 老师对本条只要求「了解」：**能说出「远距离用 Modem 调制解调」即可**。
- DTR/DSR/RTS/CTS 是**联络信号**，不是数据线，别和 TXD/RxD 混。
- 近距三线直连时 **CTS̄ 必须处理**，这是实验常见故障点。

### ④ 横向辨析

| | 近距（无 Modem） | 远距（有 Modem） |
|---|---|---|
| 联络信号 | 不用（CTS̄ 接地） | DTR/DSR/RTS/CTS 全用 |
| 电平 | TTL | RS-232 负逻辑（条目 34） |
| 传输介质 | 导线 | 电话线 / 专线 |
| 8251A 配置 | 同 | 同（只多接联络线） |

## 23. 8251A 引脚：C/D、TXD/RxD、TxRDY/RxRDY、TxE、TxC/RxC、DSR/DTR/RTS/CTS、SYNDET

**层级** 掌握 ｜ **来源** `章+网` ｜ **作业题** 第9讲Q3 ｜ **正文** §2.2

### ① 机理详解

按功能分组记忆：

**① 与 CPU 接口侧**

| 引脚 | 作用 |
|---|---|
| **D7~D0** | 数据总线 |
| **C/D**（有的书写作 C/D̄） | **口选择：=0 数据口、=1 控制/状态口**。常接地址线 A1 |
| **RD̄ / WR̄** | 读/写 |
| **CS̄** | 片选 |
| **CLK** | 芯片内部工作时钟（非收发时钟） |
| **RESET** | 复位 |

**② 发送侧**

| 引脚 | 作用 |
|---|---|
| **TxD** | 串行数据输出 |
| **TxRDY** | 发送器就绪（引脚含义见条目 28） |
| **TxE**（TxEMPTY） | 发送器空 |
| **TxC** | 发送时钟输入（常由 8253 提供） |

**③ 接收侧**

| 引脚 | 作用 |
|---|---|
| **RxD** | 串行数据输入 |
| **RxRDY** | 接收器就绪 |
| **RxC** | 接收时钟输入 |

**④ Modem 联络侧**：DTR、DSR、RTS、CTS、DCD（见条目 22）

**⑤ 同步检测**

| 引脚 | 作用 |
|---|---|
| **SYNDET** | 同步检测：内同步时作输出（找到同步字符变高），外同步时作输入 |

### ② 例题

**真题（课堂练习 8251 Q4，单选）**：以下关于 8251 引脚功能，说法**错误**的是？

```
  A TxRDY 表示发送就绪，RxRDY 表示接收就绪        ✔
  B TxD 用于发送数据，RxD 用于接收数据            ✔
  C C/D̄ 引脚用于 8251 控制/数据选择               ✔
  D A0 引脚用于 8251 控制/数据选择                ← 错的就是这项

答案：D
```

**为什么 D 错**：8251A 用 **C/D̄**（1 位）区分数据口与控制/状态口；
**A0 是 8255A / 8253 / 8259A 用的**（8255A 与 8253 用 A1A0 两根，8259A 用 A0 一根）。
把 8251A 说成用 A0，是与 8259A 记混了。

**真题（课堂练习 8251 Q1，单选）**：8251 芯片是一款？

```
答案：D（可编程串行通信芯片）

与练习 8255Q4 / 8253Q1 / 8259Q1 完全同型——四颗芯片各考一次「身份」送分题：
  8259 = 中断控制    8253 = 计数定时
  8255 = 并行        8251 = 串行
```



作业第9讲 Q3：8251 基址 300H，C/D 接 A1。求数据口与控制口地址。

```
基址 300H，C/D 接 A1：
  C/D = 0 → A1 = 0 → 数据口   = 300H
  C/D = 1 → A1 = 1 → 控制口   = 302H     ← 作业标准答案第1空 = A（302H）

（干扰项 B = 304H 是 8253 的基址，题目故意混。）
```

### ③ 易错提示

- **C/D 决定口地址**：这是计算题常客。接 A1 → 两口相差 2；接 A0 → 相差 1。
- **TxC/RxC 与 CLK 是三个不同的时钟**：CLK 是芯片内部时序，TxC/RxC 是收发移位时钟
  （决定波特率，由 8253 供）。漏掉 TxC 供给是最常见的实验故障。
- **SYNDET 在同步方式才有意义**，异步方式不用。

### ④ 横向辨析

| 概念 | 8251A | 8255A | ADC0809 |
|---|---|---|---|
| 口选择信号 | **C/D**（1 位） | **A1A0**（2 位） | ADD C/B/A（3 位，选通道） |
| 数据口数 | 1 个（收发共用） | 3 个（PA/PB/PC）+ 控制口 | 1 个（D7~D0） |
| 就绪标志 | 状态字 TxRDY/RxRDY | 方式 1/2 的 IBF/OBF | **EOC** |

**关键对比**：8251A 只有**一个数据口**，收发都走它（靠读/写区分方向）；
8255A 有**三个数据口**（靠 A1A0 选）。别把 8255 的端口选择思路套到 8251 上。

## 24. 方式字：D1D0 波特率因子、D3D2 数据位、D5D4 校验、D7D6 停止位

**层级** 掌握 ｜ **来源** `章+网` ｜ **作业题** 第9讲Q1/Q4 ｜ **正文** §2.3

### ① 机理详解

方式字是复位后**第一个**写入控制口的字，位布局（**异步**）：

```
 D7 D6 │ D5 D4 │ D3 D2 │ D1 D0
 停止位 │ 校验  │数据位 │波特率因子
```

| 位 | 取值 | 含义 |
|---|---|---|
| **D1D0** | 01 | ×1 |
| | 10 | ×16 |
| | 11 | ×64 |
| | **00** | **同步方式**（异步不用 00） |
| **D3D2** | 00 / 01 / 10 / 11 | 5 / 6 / 7 / 8 数据位 |
| **D5D4** | 00 | 无校验 |
| | 01 | 奇校验 |
| | 11 | 偶校验 |
| **D7D6**（异步） | 01 / 10 / 11 | 1 / 1.5 / 2 停止位 |

**同步方式**下各位含义改变：

| 位 | 取值 | 含义 |
|---|---|---|
| **D1D0** | 00 | 同步标志 |
| **D3D2** | 00/01/10/11 | 5/6/7/8 数据位 |
| **D5D4** | 同上 | 校验 |
| **D7** | 0 / 1 | **双 / 单同步字符** |
| **D6** | 0 / 1 | **内 / 外同步** |

**推导 38H（作业第9讲 Q2/Q4 答案）**：

```
要求：同步、同步字 2 个、偶校验、7 个数据位
  D7D6 = 00   → 双同步字符 + 内同步
  D5D4 = 11   → 偶校验
  D3D2 = 10   → 7 个数据位
  D1D0 = 00   → 同步方式
  ─────────────────────────────
  方式字 = 0011 1000B = 38H     ← 与作业标准答案一致（选项 B）
```

### ② 例题

**真题（课堂练习 8251 Q5，多选）**：Intel 8251A 在异步通信模式下，其发送时钟 TXC 频率
可以是波特率的多少倍？

```
选项：A 1 倍   B 16 倍   C 32 倍   D 64 倍

答案：ABD（1、16、64 倍）

依据：方式字 D1D0 = 波特率因子
  01 → ×1
  10 → ×16
  11 → ×64
  00 → 同步方式（异步不用）

→ 合法因子只有 1、16、64 三种，**32 倍不是 8251A 的选项**。
```

> **本题与条目 20 的 D 项联动**：那里把「TXC = 波特率 × 因子」的因子错用成 32，
> 根源就是不知道合法因子集合。**记住「1、16、64」这三个数**，
> 既能答本题，也能在计算题里排除 32 这个干扰项。
>
> 主文档 §2.3 原文：「异步 D1D0=因子（**01×1 / 10×16 / 11×64**）」——三者一一对应。



作业第9讲 Q4 原题：若要 8251A 处于同步工作方式，同步字为 2 个，用偶校验，7 个数据位，
设置工作方式的代码是？

```
MOV AL, 00111000B      ; = 38H，选项 B
OUT DX, AL
REVTIME
```

逐位验算 38H = 0011 1000：

| 位 | 值 | 含义 | 是否符合题意 |
|---|---|---|---|
| D7 | 0 | 双同步字符 | ✔ 同步字 2 个 |
| D6 | 0 | 内同步 | ✔（题未指定，默认内） |
| D5 | 1 | | |
| D4 | 1 | 偶校验 | ✔ |
| D3 | 1 | | |
| D2 | 0 | 7 个数据位 | ✔ |
| D1 | 0 | | |
| D0 | 0 | 同步方式 | ✔ |

干扰项分析（Q4 的 6 个选项）：

| 选项 | 值 | 错在哪 |
|---|---|---|
| A | 00101010B = 2AH | D3D2=10 是 7 位 ✔，但 D1D0=10 是 ×16 → **异步** ✗ |
| B | **00111000B = 38H** | **正确** |
| C | 01010111B = 57H | D1D0=11 是 ×64 → 异步 ✗ |
| D | 01100110B = 66H | D1D0=10 异步；D7D6=01 是 1 停止位 ✗ |
| E | 01110101B = 75H | 异步，且 D3D2=01 是 6 位 ✗ |
| F | 11110101B = F5H | D3D2=01 是 6 位；D7=1 单同步字符 ✗ |

### ③ 易错提示

- **同步方式的 D1D0 = 00**，而异步方式**禁用 00**（异步最小是 ×1 = 01）。
  这是判断「这道题是同步还是异步」最快的位特征。
- 本讲易错第 1 条（主文档 §2.5）：**「方式字必须复位后第一个写」**。
- **同步字的个数由 D7 定，不是由「写几个同步字符」定**——两者必须一致
  （D7=0 声明双同步字符，初始化就要写 2 个同步字符）。
- 别把 D7D6 的停止位含义套到同步方式上（同步下这两位是同步字符数/内外同步）。

### ④ 横向辨析

| | 方式字 | 命令字 | 状态字 |
|---|---|---|---|
| 方向 | **写**控制口 | **写**控制口 | **读**控制口 |
| 时机 | 复位后第一个 | 方式字之后，可反复 | 随时 |
| 位含义 | 帧格式（本条） | 运行控制（条目 25） | 状态标志（条目 26） |
| 区分手段 | 靠**先后顺序** | | |

三字共用一个口，这是 8251A 最容易错的地方——详见条目 31。

## 25. 命令字：D0 TxEN、D2 RxE、D4 ER、D6 IR(40H)、D5 RTS、D7 EH

**层级** 掌握 ｜ **来源** `章+网` ｜ **作业题** 第9讲Q1 ｜ **正文** §2.3

### ① 机理详解

命令字在方式字之后写入，可反复写以改变运行状态：

| 位 | 名称 | 作用 |
|---|---|---|
| **D0** | **TxEN** | 发送允许（1=允许发送） |
| D1 | DTR | 数据终端准备好 |
| **D2** | **RxE** | 接收允许（1=允许接收） |
| D3 | SBRK | 发送断点 |
| **D4** | **ER** | 错误复位（清 PE/OE/FE 标志） |
| **D5** | **RTS** | 请求发送 |
| **D6** | **IR** | 内部复位（**写 40H 触发**） |
| **D7** | **EH** | 进入搜索同步（同步方式用） |

**三个经典命令字的精确位模式**（来自作业标准答案）：

| 命令字 | 二进制 | 置 1 的位 | 用途 |
|---|---|---|---|
| **15H** | 0001 0101 | D0 TxEN + D2 RxE + D4 ER | **异步**：允许收发 + 清错 |
| **11H** | 0001 0001 | D0 TxEN | **只发送**（Q3 发送端） |
| **14H** | 0001 0100 | D2 RxE | **只接收**（Q3 接收端） |
| **95H** | 1001 0101 | D7 EH + D0 TxEN + D2 RxE + D4 ER | **同步**：允许收发 + 清错 + **启动搜索同步**（Q1 答案） |
| **40H** | 0100 0000 | D6 IR | 内部复位（回到初始态） |

> **15H 与 95H 的差别是 D7（EH）**。异步通信不需要搜索同步字符，用 15H；
> 同步通信必须先让芯片「搜索」同步字符，用 95H。**这是主文档 §2.3 与作业答案合起来才看清的点**。

### ② 例题

作业第9讲 Q1 原题：8251A 处于同步工作方式，已编写完成部分初始化代码，
现要求写入的命令字（**复位错误、同时启动搜索同步、使能接收和发送**）：

```
逐位累加：
  复位错误        → D4 = 1  → 0001 0000
  启动搜索同步    → D7 = 1  → 1000 0000
  使能接收        → D2 = 1  → 0000 0100
  使能发送        → D0 = 1  → 0000 0001
  ────────────────────────────────────────
  或运算          → 1001 0101B = 95H

我的答案：10010101B  ✔
正确答案：10010101B  ✔
```

### ③ 易错提示

- **同步用 95H、异步用 15H**：题目出现「同步」二字，命令字多半要加 EH 位（+80H）。
- 主文档 §2.3 只列了 15H；若考试问同步方式的命令字，**要会自己推出 95H**。
- **40H 是内部复位**，不是普通命令——写 40H 会让芯片回到初始态，
  之后必须重新写方式字（所以初始化序列里有 40H）。
- **11H / 14H 是单方向的命令字**：双机通信里发送端与接收端各写各的
  （Q3：发送 00010001B=11H，接收 00010100B=14H）。

### ④ 横向辨析

| | 命令字（写） | 状态字（读） |
|---|---|---|
| D0 | TxEN（我允许发） | TxRDY（我准备好了） |
| D2 | RxE（我允许收） | RxRDY（收到了） |
| D4 | ER（我清错误） | PE/OE/FE（出错了） |

**写命令字是「下命令」，读状态字是「看结果」**，位号有对应关系（D0/D2/D4↔D0/D1/D3-D5），
但含义完全不同。混用是最典型的错误。

## 26. 状态字：D0 TxRDY、D1 RxRDY、D2 TxE、D3 PE、D4 OE、D5 FE、D6 SYNDET、D7 DSR

**层级** 掌握 ｜ **来源** `章+网` ｜ **作业题** 第9讲Q1/Q3 ｜ **正文** §2.3

### ① 机理详解

状态字从控制口**读**出，位布局：

| 位 | 名称 | 为 1 的含义 |
|---|---|---|
| **D0** | **TxRDY** | 发送缓冲器空，可以写入新数据 |
| **D1** | **RxRDY** | 接收缓冲器已有数据，可以读走 |
| D2 | TxE | 发送器空（连缓冲器也空了） |
| **D3** | **PE** | 奇偶校验错 |
| **D4** | **OE** | 重叠错（上一字节未读又被写入） |
| **D5** | **FE** | 帧格式错（停止位不是 1） |
| D6 | SYNDET | 同步检测到 |
| D7 | DSR | 数据装置准备好 |

**三个错误位 PE/OE/FE 集中在 D5~D3**，所以用 **38H 掩码**一次测完：

```
38H = 0011 1000B → 覆盖 D5(FE)、D4(OE)、D3(PE)
TEST AL, 38H 非 0 → 有错
```

### ② 例题

作业第9讲 Q3 第 3、4 空：接收端如何判断「接收准备好」和「检查是否有错」？

```
第3空（判断 RxRDY 准备好了吗）：TEST AL, 02H    ← RxRDY 是 D1，掩码 02H
第4空（检查是否有错）        ：TEST AL, 38H    ← PE/OE/FE 三位，掩码 38H

标准答案：第3空 = E（02H），第4空 = H（38H）
```

### ③ 易错提示

- 本讲易错第 5 条（主文档 §2.5）：**「状态字 38H 掩码对应的是 PE/OE/FE 三个错误位」**——
  别以为 38H 是某个单独标志。
- **TxRDY 是 D0、RxRDY 是 D1**：发送查询用 01H，接收查询用 02H。
  Q3 的发送端就是 `TEST AL, 01H`。
- **读状态字不会清标志**：PE/OE/FE 要写命令字的 ER 位（15H 的 D4）才清除。
- 状态字是「读」，命令字是「写」，**同一个口靠读写方向区分**（见条目 31）。

### ④ 横向辨析

| 状态位 | 掩码 | 所属 | 极性 |
|---|---|---|---|
| TxRDY | **01H** | 8251A 状态字 D0 | 1 = 就绪 |
| RxRDY | **02H** | 8251A 状态字 D1 | 1 = 就绪 |
| PE/OE/FE | **38H** | 8251A 状态字 D3~D5 | 1 = 出错 |
| **EOC** | 按接线 | ADC0809 | **低 = 忙**（相反！） |
| TxRDY 引脚 | — | 8251A 引脚 | 条件更严（条目 28） |

**极性对比是重点**：8251A 的 TxRDY「高=就绪」，ADC0809 的 EOC「低=忙」，
查询循环的方向正好相反。

## 27. 三字经典值：方式字 4EH、命令字 15H、40H 内部复位

**层级** 掌握 ｜ **来源** `章+网` ｜ **作业题** 第9讲Q4 ｜ **正文** §2.3

### ① 机理详解

必须记住的五个数值，全部可用位布局现场推：

| 值 | 字 | 配置 |
|---|---|---|
| **4EH** | 方式字 | 异步：8 数据 / **无校验** / 1 停止 / ×16 |
| **7AH** | 方式字 | 异步：8 数据 / **偶校验** / 1 停止 / ×16（Q3 答案） |
| **38H** | 方式字 | 同步：双同步字符 / 内同步 / 偶校验 / 7 数据（Q2/Q4 答案） |
| **15H** | 命令字 | 异步：允许收发 + 清错 |
| **95H** | 命令字 | 同步：允许收发 + 清错 + 启动搜索同步（Q1 答案） |
| **40H** | 命令字 | 内部复位（D6=1） |

**推导 4EH**：

```
8 数据   → D3D2 = 11
无校验   → D5D4 = 00
1 停止位 → D7D6 = 01
×16      → D1D0 = 10
─────────────────────────
0100 1110B = 4EH ✓
```

**推导 15H**：

```
TxEN(D0) + RxE(D2) + ER(D4) = 0001 0101B = 15H ✓
```

### ② 例题

不查表，从位定义推出「同步、单同步字符、外同步、奇校验、8 数据位」的方式字。

```
D7 = 1       单同步字符
D6 = 1       外同步
D5D4 = 01    奇校验
D3D2 = 11    8 数据位
D1D0 = 00    同步方式
─────────────────────────
1101 1100B = DCH
```

### ③ 易错提示

- **4EH 是 8N1，7AH 是 8E1**：差一个校验位，二进制差 34H。
  Q3 考 7AH、Q4 考 38H，别只背 4EH。
- **40H 不是「命令字允许收发」**，它是**内部复位**。写 40H 之后必须重新写方式字。
- **15H 用于异步、95H 用于同步**：见条目 25。
- 记不住就从位定义推，**不要硬背二进制**——位定义本身才是必背的。

### ④ 横向辨析

| 芯片 | 经典值 | 易混点 |
|---|---|---|
| 8251A 方式字 | 4EH / 7AH / 38H | 同步与异步的位含义不同 |
| 8251A 命令字 | 15H / 95H / 40H | 15H≠95H，40H 是复位 |
| 8255A 方式字 | 90H / 82H / 80H / 9BH | 方向位 1=输入（反直觉） |
| 8253 控制字 | 36H / 74H / B6H | 先低后高 D5D4=11 |
| 8259 ICW2 | 38H | 与 8251 的 38H **数值巧合**，含义完全不同 |

**8259 的 ICW2=38H 与 8251 的方式字 38H 数值相同但毫不相干**——这是最阴险的巧合，
考试时若同时出现两题，务必按芯片分别推导。

## 28. 引脚 TxRDY ≠ 状态字 TxRDY（查询用状态字、中断驱动用引脚）

**层级** 理解 ｜ **来源** `网` ｜ **正文** §2.3

### ① 机理详解

同名不同物，条件宽严不同：

```
引脚 TxRDY 有效  =  发送缓冲器空  ∧  CTS̄ 有效  ∧  TxEN=1
                    （三个条件全满足）

状态字 D0 TxRDY =  仅反映「发送缓冲器空」
                    （一个条件）
```

所以：

- **查询编程 → 用状态字**：`IN AL,控制口` 后 `TEST AL,01H`。
  只要缓冲器空就能继续写，不受 Modem 联络信号影响，程序简单。
- **中断驱动 → 用引脚**：TxRDY 引脚可反相连 CPU 的 INTR。
  它额外要求 CTS̄ 有效，意味着「不仅我能发，Modem/对端也允许我发」，
  作为中断请求更安全（不会在不能发的时候频繁打断 CPU）。

### ② 例题

为什么双机通信（8251A）一般用查询方式而不是中断方式？

```
① 本题数据量小，查询的额外开销可接受；
② 查询用状态字 D0，条件宽松，不需要额外设中断向量、开中断、写服务程序；
③ 8251A 的 TxRDY 引脚条件严格（还要 CTS̄ 有效），近距三线直连时 CTS̄ 未接，
   引脚永远不就绪，用中断会直接失效。
```

### ③ 易错提示

- **这是单一来源条目**（只有 `网` 源），四源中无老师 PDF / 笔记 / 真题佐证。
  老师未明确要求，按「理解」准备：能说出「引脚条件更严，含 CTS̄ 与 TxEN」即可。
- 写程序时 **`TEST AL,01H` 测的是状态字**（因为 AL 是从控制口 IN 进来的），
  不是引脚。别在程序注释里写成「测 TxRDY 引脚」。
- 近距通信若用引脚式中断，记得把 CTS̄ 接地。

### ④ 横向辨析

| | 引脚 TxRDY | 状态字 D0 TxRDY |
|---|---|---|
| 条件数 | **3 个**（空 ∧ CTS̄ ∧ TxEN） | **1 个**（空） |
| 用途 | 中断请求 | 查询 |
| 可见性 | 电平引脚 | 需 IN 读状态字 |
| 近距三线直连 | 可能不就绪（CTS̄ 悬空） | 正常 |

## 29. 异步初始化 4 步：3×00H → 40H → 方式字 → 命令字

**层级** 掌握·必背 ｜ **来源** `章+网` ｜ **作业题** 第9讲Q2 ｜ **正文** §2.3

### ① 机理详解

异步初始化的固定四步（作业第9讲 Q2 的 D→B→A 段即此结构）：

```
① 向控制口连写 3 个 00H     ← 「软复位三连」，保证必定进入复位态
② 写 40H                    ← 内部复位命令（D6=1）
③ 写方式字                  ← 定义帧格式
④ 写命令字                  ← 允许收发、清错（异步用 15H）
```

**为什么先写 3 个 00H**：8251A 的「方式字 / 命令字 / 状态字」靠**先后顺序**区分
（条目 31）。若芯片当前处于未知状态，直接写方式字可能被当成命令字。
连写 3 个 00H 是一个「必中」的复位序列——无论芯片原先在哪一步，这个序列都能把它
推回到确定的初始态。这是数据手册推荐的上电初始化做法。

**REVTIME（恢复时间）**：8251A 写入需要恢复时间，连续两次写之间要插延时。
作业答案里的宏：

```asm
REVTIME MACRO
        MOV CX, 03        ; 任何非零值均可
DO:     LOOP DO
ENDM
```

### ② 例题

按作业第9讲 Q2 的排序逻辑（D→B→C→A），写出同步初始化的完整代码框架；
再写出异步 4 步的代码。

```asm
; ============ 异步初始化 4 步 ============
        MOV DX, 302H          ; 控制口（基址 300H，C/D 接 A1）
        MOV AL, 00H           ; ① 连写 3 个 00H
        OUT DX, AL
        REVTIME
        OUT DX, AL
        REVTIME
        OUT DX, AL
        REVTIME
        MOV AL, 40H           ; ② 内部复位
        OUT DX, AL
        REVTIME
        MOV AL, 4EH           ; ③ 方式字：8N1 ×16
        OUT DX, AL
        REVTIME
        MOV AL, 15H           ; ④ 命令字：允许收发 + 清错
        OUT DX, AL
        REVTIME
```

### ③ 易错提示

- **四步顺序不能乱**：方式字必须在复位之后、命令字之前。
  本讲易错第 1 条（主文档 §2.5）：「方式字必须**复位后第一个写**（顺序分）」。
- **3 个 00H 不能省成 1 个**：作业标准答案明确写了三次（Q2 选项 D）。
- **每次写之间要 REVTIME**：漏了在高速 CPU 上会写入失败。
- 命令字异步用 **15H**；若题目说同步，换成 **95H**（条目 25）。

### ④ 横向辨析

| 步骤 | 异步 | 同步 |
|---|---|---|
| 1 | 3×00H | 3×00H |
| 2 | 40H | 40H |
| 3 | 方式字（4EH 型） | 方式字（38H 型） |
| 4 | 命令字（15H） | **写同步字符（1~2 个）** |
| 5 | — | 命令字（95H） |
| **总步数** | **4** | **5** |

**多出来的第 4 步就是写同步字符**，且写的个数必须与方式字 D7 声明的一致。

## 30. 同步初始化 5 步：前 3 步同 + 同步字符（1~2 个）+ 命令字

**层级** 掌握 ｜ **来源** `章+网` ｜ **作业题** 第9讲Q2 ｜ **正文** §2.3

### ① 机理详解

同步比异步多一步——**写同步字符**：

```
① 3×00H      （软复位三连）
② 40H        （内部复位）
③ 方式字     （38H：双同步字符 + 内同步 + 偶校验 + 7 数据位）
④ 同步字符   （方式字 D7=0 → 写 2 个；D7=1 → 写 1 个）
⑤ 命令字     （95H：允许收发 + 清错 + 启动搜索同步）
```

作业第9讲 Q2 的完整答案（我的答案 DBCA，正确答案 DBCA）：

| 段 | 内容 |
|---|---|
| **D** | 控制口写入三次 0 |
| **B** | 控制口写入复位字 40H |
| **C** | 方式字 `0011100B`（应为 00111000B = 38H）+ 写 2 个同步字符 16H |
| **A** | 命令字 `10010101B`（= 95H）：启动搜索同步、复位错误标志、使能收发 |

> 平台答案把方式字印成 `0011100B`（7 位，漏了一个 0），
> 但 Q4 的单选题确认正确值是 **00111000B = 38H**。按 38H 记忆。

### ② 例题

把作业第9讲 Q2 排好序的代码整理成可读形式（控制口 82H）：

```asm
        MOV DX, 82H           ; 控制口地址
        ; ── D：控制口写入三次 0 ──
        MOV AL, 00H
        OUT DX, AL
        REVTIME
        OUT DX, AL
        REVTIME
        OUT DX, AL
        REVTIME
        ; ── B：控制口写入复位字 40H ──
        MOV AL, 40H
        OUT DX, AL
        REVTIME
        ; ── C：控制口写入方式字（双同步字符、内同步、偶校验、7 数据位）──
        MOV AL, 00111000B    ; = 38H
        OUT DX, AL
        REVTIME
        ; 控制口写入同步字符（2 个字符）
        MOV AL, 16H          ; 同步字符自定义
        OUT DX, AL
        REVTIME
        OUT DX, AL           ; 同一个字符写第二遍
        REVTIME
        ; ── A：控制口写入命令字 ──
        MOV AL, 10010101B    ; = 95H，启动搜索同步 + 复位错误 + 使能收发
        OUT DX, AL
        REVTIME
```

### ③ 易错提示

- **同步字符要写的个数必须与方式字 D7 一致**：D7=0 → 2 个，D7=1 → 1 个。
  Q2 的 38H 是 D7=0，所以写**两个** 16H。
- **同步方式的命令字是 95H 不是 15H**（要 EH 启动搜索同步）。
- **方式字漏一个 0 是最容易的笔误**：38H 是 8 位二进制，写成 7 位在汇编里会报错或含义全变。
- Q2 是排序题，错一步全错——**按 3×00H → 40H → 方式字 → 同步字符 → 命令字**的顺序记。

### ④ 横向辨析

| | 异步 4 步 | 同步 5 步 |
|---|---|---|
| 同步字符 | 无 | **1~2 个**（由方式字 D7 定） |
| 命令字 | 15H | 95H |
| 方式字 | 4EH / 7AH | 38H |
| SYNDET 引脚 | 不用 | **用**（检测同步） |
| 顺序铁律 | 复位 → 方式字 → 命令字 | 复位 → 方式字 → **同步字符** → 命令字 |

## 31. 方式字/命令字/状态字共用同一个口，靠先后顺序区分

**层级** 掌握 ｜ **来源** `章+网` ｜ **作业题** 第9讲Q2 ｜ **正文** §2.3

### ① 机理详解

8251A **只有一个控制口**（C/D=1），但要从这个口写两种字、读一种字。
芯片内部没有「命令寄存器编号」，只能靠**状态机的先后顺序**判断收到的是什么：

```
复位 ──► 期待「方式字」 ──► 期待「同步字符」(仅同步) ──► 期待「命令字」 ──┐
   ▲                                                                    │
   └──────────────────── 写 40H（内部复位）──────────────────────────────┘
```

- **写**：顺序是 复位 → 方式字 → （同步字符）→ 命令字。命令字之后可以一直写命令字，
  直到再次写 40H 回到复位态。
- **读**：读控制口永远是状态字，与写的顺序无关（靠 RD̄ 方向区分）。

**这正是「初始化顺序不能乱」的根本原因**：如果芯片期待方式字时你写了命令字，
它会把命令字当成方式字解释，之后所有通信参数全错——而且**不会有任何报错**。

### ② 例题

某程序上电后直接 `MOV AL,4EH; OUT 控制口,AL`（跳过 3×00H 与 40H），可能发生什么？
如何规避？

```
可能：芯片上电后的内部状态不确定。
  · 若恰好已处于复位态 → 4EH 被正确当作方式字，程序碰巧能跑；
  · 若处于命令字态   → 4EH 被当作命令字（TxEN=0! RxE=0!），收发全禁止，
                        且方式字从未写入 → 通信失败且无报错。
规避：严格按初始化序列写——3×00H + 40H 必定把芯片推回复位态，
      之后再写方式字。这是数据手册推荐的上电做法，不是可选优化。
```

### ③ 易错提示

- **「共用一个口」不是说三个字能随便交替写**。方式字只在复位后写一次有效。
- **写 40H 会回到复位态**，之后必须重新写方式字——在运行中误写 40H 会让通信中断。
- 读状态字不受顺序影响，但**读操作不会改变写状态机**。
- 这是 8251A 与 8255A 最大的结构差异：8255A 靠 **A1A0** 选寄存器，8251A 靠**顺序**。

### ④ 横向辨析

| | 8251A | 8255A | 8259A |
|---|---|---|---|
| 寄存器选择 | **靠先后顺序** | 靠 **A1A0** | 靠 **A0** + 顺序（ICW 序列） |
| 同口多字 | 方式字/命令字/状态字 | 方式字/BSR（靠 D7） | ICW/OCW（靠顺序与位特征） |
| 顺序错后果 | 参数全错、无报错 | 方式字被当 BSR | 初始化失败 |

**8255A 的方式字与 BSR 也是共用一个控制口**，但它用 **D7** 区分（D7=1 方式字、D7=0 BSR），
比 8251A 的「纯顺序」更 robust。三者对比记忆。

## 32. 发送端查询 TxRDY（TEST AL,01H）

**层级** 掌握 ｜ **来源** `章+网` ｜ **作业题** 第9讲Q3 ｜ **正文** §2.4

### ① 机理详解

发送端的工作循环：

```
① 读状态字（IN AL, 控制口）
② TEST AL, 01H        ← 测 TxRDY（D0）
③ JZ 继续等            ← 为 0：发送缓冲器还满，不能写
④ 就绪：取待发字节（MOV AL, [SI]）
⑤ OUT 数据口, AL      ← 写入发送缓冲器
⑥ INC SI              ← 源指针后移
⑦ 循环 / 按长度计数
```

关键点：

- **必须查状态字再写**：发送缓冲器只有一个字节深度，上一字节还没搬进移位寄存器时
  写入会**丢数据**（不是覆盖，是丢失）。
- **指针用 SI 或 BX**：源数据在内存，用 `LEA SI, BUF_T` 或 `MOV BX, OFFSET BUF_T`。
- **循环控制**：`LOOP` 配 CX 作计数器，或用长度寄存器。

### ② 例题

作业第9讲 Q3 第（1）问：从发送缓冲器 BUF_T 发送一个数据（控制口 302H、数据口 300H）。

```asm
        LEA DI, BUF_T
NEXT_T: IN  AL, DX           ; DX = 302H（控制口）
        TEST AL, 01H         ; 测试 TxRDY 发送准备好了吗
        JZ  NEXT_T           ; 未就绪 → 继续等
        MOV DX, 300H         ; 数据口
        MOV AL, [DI]         ; 取待发字节
        OUT DX, AL           ; 发送
        INC DI               ; 指针后移（发多个字节时）
```

> 作业标准答案即此结构。注意 `IN AL,DX` 与 `TEST AL,01H` 之间 DX 必须是**控制口**，
> 发数据前才把 DX 改成数据口——这是「蓝色加粗，历年易写错的地方」。

### ③ 易错提示

- **掩码是 01H 不是 02H**：01H 测 TxRDY（D0，发送），02H 测 RxRDY（D1，接收）。
  收发两端正好差一位。
- **查状态前 DX 要是控制口**：Q3 的标准答案在 `IN AL,DX` 前 DX=302H，
  发数据时才 `MOV DX,300H`。把 DX 一直设成数据口是经典错误。
- **TxRDY 是状态字 D0**，与引脚 TxRDY 条件不同（条目 28）——查询用状态字即可。
- **INC DI / INC SI 别忘**：发多个字节时不移指针会反复发同一个数。

### ④ 横向辨析

| | 发送端 | 接收端 |
|---|---|---|
| 查询掩码 | **01H**（TxRDY） | **02H**（RxRDY） |
| 就绪含义 | 发送缓冲器空 | 接收缓冲器有数据 |
| 就绪后动作 | `OUT 数据口, AL` | `IN AL, 数据口` |
| 错误检查 | 一般不查 | **先查 38H 再查 02H**（条目 33） |
| 指针方向 | SI/DI → 源 | SI/DI → 目的 |

## 33. 接收端先查错误（TEST AL,38H）再查 RxRDY（02H）

**层级** 掌握 ｜ **来源** `章+网` ｜ **作业题** 第9讲Q3 ｜ **正文** §2.4

### ① 机理详解

接收端比发送端多一步——**先查错误**：

```
① 读状态字（IN AL, 控制口）
② TEST AL, 38H        ← 先测 PE/OE/FE 三个错误位（D5~D3）
③ JNZ ERROR           ← 有错 → 转错误处理（不清错误会一直报错）
④ TEST AL, 02H        ← 再测 RxRDY（D1）
⑤ JZ 继续等            ← 无数据 → 继续等
⑥ IN AL, 数据口        ← 读走数据
⑦ MOV [DI], AL        ← 存入内存
⑧ INC DI              ← 目的指针后移
```

**为什么必须先查错误**：

- **PE/OE/FE 是累积标志**，不会因读状态字而自动清除。一旦置位，如果不处理
  （写命令字的 ER 位清标志），后续每次查都是「有错」。
- **OE（重叠错）尤其危险**：上一字节还没被读走，新字节又到了，数据已**真的丢了**。
  若只查 RxRDY 不查 OE，会把丢数据的字节当成正常数据收下。
- 先查错误可以在**读数据之前**发现「这一帧可能不可靠」，避免把错数据写进缓冲区。

### ② 例题

作业第9讲 Q3 第（2）问：数据存入接收缓冲器 BUF_R，接收出现错误时跳转 ERROR。

```asm
        LEA DI, BUF_R
NEXT_R: IN  AL, DX           ; DX = 302H（控制口）
        TEST AL, 38H         ; 先检查是否有错（PE/OE/FE）
        JNZ ERROR            ; 有错 → 转错误处理
        TEST AL, 02H         ; 再测 RxRDY 接收准备好了吗
        JZ  NEXT_R           ; 无数据 → 继续等
        MOV DX, 300H         ; 数据口
        IN  AL, DX           ; 读走数据
        MOV [DI], AL         ; 存入接收缓冲器
        INC DI               ; 指针后移
```

作业四个空的标准答案：第1空 = **302H**、第2空 = **7AH**、第3空 = **02H**、第4空 = **38H**。

### ③ 易错提示

- **顺序不能反**：先 38H 后 02H。反过来会在有错时也可能读到「看似就绪」的状态，
  且 OE 已经造成数据丢失。
- **38H 是三个错误位的掩码**（D5 FE、D4 OE、D3 PE），不是单个标志（本讲易错第 5 条）。
- **ERROR 处理程序里要清错误**：写命令字 ER 位（如再写一次 15H/95H），
  否则错误标志不清，程序卡在 ERROR。
- **DX 的两段切换**：查状态用控制口，收发用数据口。Q3 的标准答案在收发前都重新
  `MOV DX,300H`。

### ④ 横向辨析

| | 发送端 | 接收端 |
|---|---|---|
| 第一次 TEST | 01H（TxRDY） | **38H（错误）** |
| 第二次 TEST | 无 | 02H（RxRDY） |
| 出错后果 | 写入丢失（可重试） | **数据已丢（OE 不可重试）** |
| 错误清除 | 不需要 | 命令字 ER 位 |

**根本差异**：发送是「我主动写，未就绪就等」；接收是「对端主动发，来不及时就丢」。
所以接收必须更谨慎——先确认没错，再确认有数。

## 34. RS-232 是负逻辑（−3~−15V 为 1）

**层级** 了解 ｜ **来源** `网` ｜ **正文** §2.5

### ① 机理详解

**RS-232C 是负逻辑**，与 TTL 正逻辑相反：

| 逻辑 | RS-232 电平 | TTL 电平 |
|---|---|---|
| **1** | **−3V ~ −15V** | +2.4V ~ +5V |
| **0** | **+3V ~ +15V** | 0V ~ +0.4V |

所以 8251A 的 TTL 串行信号要经 **电平转换器**（MC1488 / MC1489、MAX232 等）
才能上 RS-232 总线。MAX232 用电荷泵把 +5V 升到 ±10V，单电源即可。

本讲易错第 4 条（主文档 §2.5）原文：**「RS-232 是负逻辑（−3~−15V 为 1）」**。

**空闲/起始位在 RS-232 上的表现**：异步空闲是高电平 1 → RS-232 上是 −12V 左右；
起始位 0 → +12V 左右。所以示波器上看串口波形，「有数据」时先出现一个正向跳变。

### ② 例题

用示波器测 RS-232 串口，空闲时看到约 −12V，来数据时先跳到 +12V。请解释。

```
空闲位 = 逻辑 1 → RS-232 负逻辑 → −12V ✓
起始位 = 逻辑 0 → RS-232 负逻辑 → +12V ✓
即「先跳到 +12V」正是起始位的下降沿（在负逻辑下表现为上升沿）。
```

### ③ 易错提示

- **这是单一来源条目**（只有 `网` 源）。老师只要求「了解」，记住「负逻辑、−3~−15V 为 1」即可。
- **别把 RS-232 的电平与 TTL 混**：TTL 是 +5V/0V 正逻辑，直接对接会烧器件或无法通信。
- RS-232 是**电气标准**，不是协议；它只管电平，不管帧格式（帧格式由 8251A 定）。

### ④ 横向辨析

| | TTL | RS-232 |
|---|---|---|
| 逻辑 1 | +5V | **−3~−15V** |
| 逻辑 0 | 0V | +3~+15V |
| 逻辑制 | 正 | **负** |
| 传输距离 | 数米 | 数十米 |
| 转换器件 | — | MC1488/1489、MAX232 |
